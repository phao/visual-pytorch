ExperimentSpec6 and RunRecord6 explicitly select the separately checked
Family8/Specialization7/TaskBundle4 runtime-v2 route. Container20 fences their
retained meaning; no new SQL table or sidecar. This is retained Stage D work,
not completion of original D or E. Earlier1–5 contracts and captured archives
remain available unchanged; opening old valid files never rewrites their bytes.

## Explicit selection, not constructor inference

A family selection retains its exact reference, fixed bindings, ordered axes
and this additional explicit choice:

```json
{
  "id":"chosen-lstm",
  "family":{"kind":"family","id":"family-id","revision":"EXACT_SHA256"},
  "bindings":{"time":5,"width":2,"cell-width":3,"layers":1,
              "projection":2,"directions":true,"bias":true},
  "axes":[],
  "execution":"runtime-temporal-v2"
}
```

The enclosing experiment must have integer version6. The family must be exact
Family8 with a nonnull v2 policy and its specialization must resolve to exact
Specialization7/proof2/witness3. Changing a time binding alone does not opt in.
Omitted execution remains concrete baseline, even in6. Newer experiments may
still deliberately choose concrete/spatial/v1 policies, under those policies'
unchanged exact provenance requirements. Family7/v1 typed proof restrictions
are not silently widened by this extension.

Selection order, exclusions, whitelists, independent initialization seeds,
task pairings, splits and protocol grammar remain unchanged. Actual times come
from explicit retained field/transform bindings, not drawing position or an
unannounced constructor rebind. Two different datasets can share the same frozen
constructor/model/specialization while having different TaskBundle4 identities.
Every state/control/input/head remains explicitly bound; no automatic labels,
execution lengths, objective masks or group/time split inference.

Preview is pure: incompatible constructor/state/target combinations stay visible;
no tensors, fitting or SQL writes. Candidate identity still hashes the exact
experiment reference and ordered coordinate values. Exact TaskBundle4 provenance
then distinguishes model/data/task/manifest/protocol and runtime proof.

## Retention and file compatibility

RunRecord6 must match its exact selected ExperimentSpec6. It retains the existing
resolved references, split manifest, protocol and ordered terminal attempts;
successful results retain RunIdentity4 and inference-only Checkpoint1. Admission
reconstructs derived model/specialization references from the pinned family;
worker-supplied extra rows cannot replace them. Retaining missing derived rows
and the terminal run is atomic, including late failures/dirty/history state.

Explicit retry preserves the old selection, resolved references and manifest.
Moving family/experiment heads does not substitute them. A changed manifest or
another candidate cannot become a retry of the old run. Completed, cancelled,
unavailable supervision and admission/worker/execution failures retain distinct
existing evidence semantics. This is not optimizer continuation or parameter
freezing. The current task trainer still owns all declared learnable parameters.

Container20 is required for any retained ExperimentSpec/RunRecord6, including
unmaterialized or concrete-policy6 objects. Older headers carrying them fail
closed before returning a usable workspace; source bytes are untouched. Family8/
Specialization7 still independently require19. Valid older workspaces upgrade
only their working header; explicit Save writes20. Model/data/task/protocol/report
recipe/operator versions and registry table structure are unchanged.

## Portable reports and real kernels

ReportRecipe1 remains unchanged. Captured report closures include the exact
experiment/run/family/specialization/model/data/task revisions and every selected
v2 helper. A saved result report does not train; an explicit rerun selects the
captured candidate and launches its existing isolated task-v4 worker. Historical
archives keep their own captured bytes; adding6 does not patch old archives.

Companions distinguish the frozen constructor-baseline architecture from
`runtime-architecture-<run-sha>.py`, the actual task compiler, and
`predictor-<run-sha>.py`, the checked saved weights plus fitted input pipeline.
The new route extends the report companion version branch to include TaskBundle4;
the first real-kernel regression detected that missing branch. Companions use
the same compiler/exporter rather than approximate a visually similar forward.
Checkpoint, metrics and supervised populations are checked across actual saved/
rerun kernels; merely parsing notebook cells is not execution evidence.

## Verification boundaries

New pure checks cover exact version/policy admission, independent dataset times,
constructor axes/order, historical revisions, owned atomic upgrades/invalid
drafts, unmaterialized container20 fences and real stdlib/read-only CLI preview.
New numerical checks cover actual worker/local equality, CLI run/reload/export/
fresh variable-T prediction, retries, unavailable/admission failures, forgery,
late atomic rollback and genuine saved/rerun Jupyter kernels with exact checkpoint/
metric/predictor replay. Actual sandboxed Qt drives both v1 and v2 editor choices,
preview without writes, retention, real training and .vtw reload without importing
Torch in the GUI process. A pure legacy probe compares55 old1–5 points/receipts/
bundles against committed pre-v2 modules (not a whole historical environment).

Acceptance counts, actual integration/source identity and raw initial failures
are recorded in development/campaign evidence. These checks do not substitute
for original D's remaining grouped-temporal/CNN–RNN/convergence gates or E's
durable heavyweight backend, lifecycle, continuation and reduction benchmarks.
